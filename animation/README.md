# Анимации — пајплајн и архитектури

Две самостојни HTML страници, наменети да се **снимат од екран** и да се
користат како видео (на пример при одбрана).

```
animation/
    index.html     ПРЕГЛЕД — целиот пајплајн во 10 сцени (≈ 3:25)
    models.html    ДЛАБОКО — 36 чекори низ четирите модели, тензор по тензор (≈ 5:16)
    README.md      овој опис
```

**`index.html`** одговара на прашањето *што се случува*: од CSV по базна станица,
преку поделбата и прозорците, до одлуката во мрежата. Секој модел добива по една
сцена со својот карактеристичен механизам.

**`models.html`** одговара на прашањето *како точно*: секој модел се поминува
чекор по чекор, со **вистинскиот облик на тензорот** на секој чекор — од
`[6, 24, 3]` на влез до `[6, 1, 1]` што влегува во загубата. Направена е за
некој што сака да го чита кодот покрај анимацијата.

Двете се поврзани — линк горе лево на секоја страница води до другата.

## Отворање

Двоен клик на `index.html` (или `models.html`), или:

```powershell
Start-Process .\animation\index.html
Start-Process .\animation\models.html
```

Нема сервер, нема зависности, нема мрежни повици — страниците работат и офлајн.

## Управување

| Дејство | Копче |
|---|---|
| Пушти / паузирај | `Space` или ▶ |
| Следен / претходен чекор | `→` / `←` или ‹ › |
| Следен / претходен **модел** (само `models.html`) | `Shift+→` / `Shift+←` или ‹‹ ›› |
| Од почеток | `Home` |
| Скок | лентата горе десно, или лентата со чекори долу |
| Брзина | `0.6×` / `1×` / `1.6×` |

Двете страници се пуштаат автоматски и се вртат во круг.
Брзината ги менува и анимациите и должината на чекорите заедно, па сликата и
темпото остануваат синхрони.

## Снимање

1. Отвори ја во browser и притисни `F11` (цел екран).
2. Стартувај снимач — на Windows `Win+Alt+R` (Xbox Game Bar) или OBS.
3. Притисни `Home`, па `Space`.

Позадината се прилагодува на светла/темна тема на системот. За снимање
најчисто изгледа во светла тема ако видеото оди во печатена презентација.

## Чекори во `models.html`

Секој чекор покажува влезен тензор → операција → излезен тензор, со точните
облици за `batch_size = 6`, `seq_len = 24`, `pred_len = 1`, `d_model = 32`.

| Модел | Чекори | Што се следи |
|---|---|---|
| **PatchTST** | 11 | RevIN → дополнување → 20 закрпи → `W_P` → канална независност (`[18, 20, 32]`) → PE → енкодер ×3 → Flatten(640) → де-норм |
| **CATS** | 8 | истите закрпи стануваат само K и V → научен `nn.Parameter[1,6]` како прашалник → скорови `[18, 4, 1, 20]` → QAM/GEGLU → резидуални скорови → проекција во 6 часа, се зема првиот |
| **DeformableTST** | 8 | `[18, 1, 24]` → stem k=1 (без намалување) → LPU → `conv_offset` → `grid_sample` на дробни позиции → внимание `[72, 24, 24]` + rpb → DWC-MLP → Flatten(768) |
| **Peri-midFormer** | 9 | временски марки → декомпозиција → `rfft` → `top_k=2` периоди `[24, 8]` → пирамида `[6, 4, 32, 3]` → маска → енкодер ×3 → периодични текови `[18, 3, 64]` → + тренд |

Peri-midFormer е единствениот чија форма **зависи од податоците** — периодите ги
одредува FFT, па друга станица може да даде друга пирамида. Приказот користи
конкретен пример (периоди `[24, 8]` → `components_per_level = [1, 3]`) и тоа е
обележано на самиот чекор.

## Точност на прикажаното

Сите параметри, облици и правила се земени директно од кодот
(`SHARED_ARGS` и `MODEL_CONFIGS` во `run.py`, `Exp_Main` во `exp/exp_main.py`,
`Dataset_Custom` во `data_provider/data_loader.py`, `analysis/*`).

Облиците на тензорите во `models.html` се изведени од самите `forward` методи
(`PatchTST_backbone.forward`, `Model_backbone.forward` во CATS,
`DeformableTST.forward`, `Model.forecast` + `Encoder.forward` во Peri-midFormer).

Шематски се само овие, и тоа е обележано на самото место:

- кривите на загуба во сцена 07 на `index.html` — ја покажуваат формата и
  точката на рано запирање, не измерени вредности;
- столбовите со `RSE` во сцена 09 — го покажуваат правилото за избор
  (`sort_values("rse_mean")`), не резултат од кампања;
- вредностите во матриците на вниманието во `models.html` — покажуваат
  **облик и структура** (дијагонална доминантност), не научени тежини.

Сите останати бројки (24 → 1 час, 20 закрпи, `640 = 20 × 32`, `768 = 24 × 32`,
`top_k = 2`, праг на 20-ти перцентил, `patience = 50`, `lr = 5e-4`, …) се
вистинските вредности од кодот.
